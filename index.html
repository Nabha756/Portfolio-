    AJava · distributedsource ↗

    FlowSync

    A job-processing service that runs jobs asynchronously through RabbitMQ and retries the ones that fail.

    Java 21Spring Boot 3RabbitMQPostgreSQLRedisDocker

    Problem

    Retrying a failed job inside the worker blocks it from processing other jobs, and retrying straight away often fails again for the same reason.

    Approach

    Failed jobs go to a retry queue with a 10 s message TTL, after which RabbitMQ sends them back to the job queue. After 3 retries a job is moved to a dead-letter queue.

    Also

    Each attempt is saved to an execution history table in PostgreSQL. Job status is cached in Redis, and job records use @Version optimistic locking.

    Customer Behavior Analytics

    A Flask and MongoDB application that tracks user activity and predicts customer churn.

    PythonFlaskMongoDB · PyMongoScikit-learnSocket.IOJWT

    Problem

    The most frequent query fetches a user's most recent activity. Without a suitable index, MongoDB has to scan all events and sort them in memory.

    Approach

    A compound index on (user_id, timestamp desc) returns a user's events already sorted. A unique index on email prevents duplicate accounts.

    Also

    K-Means customer segmentation and a Random Forest churn model, served through JWT-authenticated APIs, with live updates over Socket.IO.

    PayCore

    A command-line payment processing simulator written in C++17.

    C++17STLCMakeGoogleTest · 51 tests

    Design

    Payment and Refund derive from Transaction. Validation, processing, transaction management and file storage are separate classes, each with its own tests.

    Money

    Amounts are stored as integer paise to avoid floating-point rounding errors. Only masked account numbers are saved to disk.

    Refunds

    Partial refunds are supported. A refund larger than the remaining refundable amount is rejected before any state changes.
